# MFTG-Net: Multi-Energy Load Forecasting

This repository contains the implementation and reproducibility materials for
MFTG-Net, a multi-energy load forecasting model for electricity, cooling, and
heating loads. The implementation uses Python and PyTorch.

## Requirements

Install the dependencies listed in `requirements.txt`. The original
environment used Python 3 and PyTorch; CUDA is optional, and `--device cpu`
can be used on a machine without a GPU.

## Data Preparation

Place the hourly input CSV at:

```text
data/dataset_input_jiuzheng.csv
```

The first three columns must be the target loads (`KW`, `CHWTON`, and
`HTmmBTU`). The remaining columns are the environmental, calendar, system,
and GHG covariates used by the model. The processed CSV used by the training
script is included in `data/`. If the local copy is stored elsewhere, pass its
path with `--data PATH`.

## Training

The main entry point is `train.py`. The revised manuscript protocol uses a
chronological 5:2:3 train/validation/test split, a 168-hour look-back window,
and 24-, 48-, 72-, or 96-hour forecasting horizons. Example commands are:

```text
python train.py --horizon 24 --seed 2020 --run_id 1
python train.py --horizon 48 --seed 2020 --run_id 1
python train.py --horizon 72 --seed 2020 --run_id 1
python train.py --horizon 96 --seed 2020 --run_id 1
```

On a CPU-only machine, append `--device cpu`. The default data path can be
overridden with `--data PATH`.

## Reproducibility record

The full protocol is also documented in [`REPRODUCIBILITY.md`](REPRODUCIBILITY.md).

The training script accepts `--seed` and `--run_id` arguments. Each completed run writes
`output/<model>_<horizon>_<window>/result/reproducibility_run<run_id>.json`,
which records the input and target columns, chronological split, selected
hyperparameters, optimizer and scheduler settings, stopping rule, trainable
parameter count, execution environment, seed, and final test metrics. For
independent runs, use the preregistered seeds 2020, 2021, and 2022 with unique
run identifiers:

```text
python train.py --seed 2020 --run_id 1
python train.py --seed 2021 --run_id 2
python train.py --seed 2022 --run_id 3
```

Use `--horizon 24`, `--horizon 48`, `--horizon 72`, or `--horizon 96` for
the four forecasting horizons; the script updates the model output length and
output directory consistently.

The implementation does not perform an automated hyperparameter sweep. The
selected configuration is fixed before test evaluation and is recorded as a
singleton search space in each manifest; the test set is not used for model or
hyperparameter selection.

The shared training protocol is Adam with learning rate `1e-3`, weight decay
`1e-5`, batch size `256`, at most `60` epochs, gradient clipping at `5`, and
ReduceLROnPlateau with factor `0.5` and patience `4`. There is no early
stopping; the checkpoint with the lowest validation MAE is retained. The loss
is weighted MAPE plus `0.0005` times weighted MAE. Architecture-specific
settings are recorded in each manifest. Baselines implemented outside this
repository should be accompanied by their exact implementation and settings
when their results are reported.

After completing the independent runs, create a checkable summary with:

```text
python summarize_reproducibility.py --root ./output --expected-runs 3
```

Directories with fewer than three manifests are marked incomplete in the
generated CSV and must not be reported as three-run averages. The summary
script does not invent missing runs or aggregate incomplete experiments.

## Reproducibility scope

The repository provides the training entry point, model and utility modules,
processed input CSV, dependency list, fixed protocol, random-seed controls,
chronological split, and manifest/summary tools. Generated checkpoints are not
stored in the repository; they can be regenerated by running `train.py` with
the commands above.
